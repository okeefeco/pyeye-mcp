## A. MUST fix before v2.2.0 (user-facing pages)

**README.md**
- **[7] R [MUST]:** "the MCP server uses your project's environment" is not guaranteed. The `.mcp.json` runs a bare `python`, so the server uses the project venv only if the client was launched from a shell with it active. The fix: use the venv's Python path.
- **[1] R [MUST]:** the config loading order stops at auto-discovery. `ProjectConfig.load_config` applies a 5th source, the session's unsaved `configure_packages(save=False)` additions (#953). That's new in this release, so the list is missing a v2.2.0 feature.
- **[2] R:** auto-discovery returns early on a `src/` layout with no sibling packages, and adds virtualenv site-packages otherwise (`_auto_discover`, verified).
- **[3] R:** pyproject `build-backend` detection runs only when pyproject is the project's config file and no `packages` are set yet.
- **[6] R:** `PYEYE_ENABLE_PERFORMANCE_METRICS` registers every admin tool (`ADMIN_TOOLS`: `get_performance_metrics` and `get_connection_diagnostics`), not just one.
- **[4] R (low):** `callers`/`references` are presented as the only deferred edges.
- **[0] N:** the badge's "3.11+" matches `requires-python` today; it's a maintenance suggestion. **[5]** N/style. **[8][9]** N: dated third-party claims, a judgment call.
