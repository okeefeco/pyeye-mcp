# Dogfooding Metrics Setup Guide

This guide helps you set up automatic metrics tracking for the PyEye dogfooding initiative.

## 🚀 Quick Setup (Recommended)

Run the automated setup script:

```bash
bash scripts/setup_dogfooding.sh
```

This will:

- Install the project's git hooks with `pre-commit install`, including the post-checkout hook that starts a session on issue branches
- Add shell aliases to `~/.bashrc` or `~/.zshrc`: a `grep` and a `cd` wrapper, and the `dogfood-*` commands
- Install wrappers for `grep`, `egrep`, `fgrep` and `rg` in `~/.local/bin` that count code searches, then run the real command
- Create the metrics directory
- Test the installation

> **If you ran this setup before #969:** the wrappers it installed broke `grep`,
> `egrep`, `fgrep` and `rg`: every call failed with "not found" (exit 127), and
> nothing was counted. Re-run `bash scripts/setup_dogfooding.sh` to install
> fixed wrappers, or delete `~/.local/bin/{grep,egrep,fgrep,rg}` to remove them.

## ⚡ What Gets Automated

After setup, these things happen automatically:

### 1. Branch Switching

```bash
git checkout feat/123-new-feature
# 📊 Starting dogfooding metrics for issue #123...
```

### 2. Manual Search Tracking

```bash
grep "function_name" src/
# (automatically logs grep usage)
```

### 3. Session Handover

Starting a session saves any session that is still open to `history.jsonl`
first, so switching to the next issue branch never discards the previous
session's data. To end a session yourself and see its summary, run `dogfood-end`
(the numbers below are an example):

```bash
dogfood-end
# === Session Summary ===
# Duration: 45.2 minutes
# MCP queries: 12
# Grep/manual searches: 3
# MCP adoption rate: 80.0%
# Bugs prevented: 1
# Time saved: 15 minutes
```

"MCP queries" counts only the queries logged with the CLI's `mcp` command. The
CLI can't see the calls Claude makes; the Claude Code hooks count those
(`mcp-report`, see [scripts/claude_hooks/README.md](../scripts/claude_hooks/README.md)).

### 4. Project Entry

```bash
cd ~/repos/pyeye-mcp
# 📊 Auto-starting dogfooding metrics for issue #135...
```

## 🔧 Manual Commands

Even with automation, you have manual control:

```bash
# Start/stop sessions manually
dogfood-start --issue 123
dogfood-end

# Log specific events
dogfood-saved 10 "Traced the call chain with MCP instead of grep"
dogfood-bug "MCP showed a re-export pointed at the wrong definition"

# Generate reports
dogfood-report --days 7
```

The `dogfood-*` aliases run this checkout's `scripts/dogfooding_metrics.py`, so
they work from any directory. They were called `mcp-*` before #982; `mcp-report`
is now only the Claude Code hooks' report. If your shell config still has the old
names, see Updating below.

## 📁 Files Created

The setup creates these files:

### Git Hooks

All git hooks are generated by `pre-commit install` from `.pre-commit-config.yaml`.
The one that matters here is `post-checkout`, which starts a session when you
switch to an issue branch (`type/<issue>-description`).

> **If you ran the old `scripts/install_hooks.sh`:** it replaced
> `.git/hooks/pre-commit` with a script that skipped every pre-commit check
> (secret scanning, linting, type-checking). It has been removed (#578). Restore
> your hooks with `uv run --frozen pre-commit install`, and check that
> `.git/hooks/pre-commit` starts with `# File generated by pre-commit`.

### Shell Aliases (in ~/.bashrc or ~/.zshrc)

- `grep` wrapper - Counts every `grep` run in a directory with `scripts/dogfooding_metrics.py`
- `cd` wrapper - Auto-starts sessions when entering project
- `dogfood-*` commands - Quick access to metrics functions

With the search wrappers below also installed, a code search in the project is
counted twice, once by each ([#1020](https://github.com/okeefeco/pyeye-mcp/issues/1020)).

### Search wrappers (in ~/.local/bin)

- `grep`, `egrep`, `fgrep` and `rg` - Count searches that look like code
  searches, then run the real command
- An `export PATH="$HOME/.local/bin:$PATH"` line in `~/.bashrc` and `~/.zshrc`
  (where they exist), if `~/.local/bin` isn't on your PATH yet

### Metrics Data

- `~/.pyeye/metrics/` - Directory for all metrics data
- `current_session.json` - Active session data
- `history.jsonl` - All completed sessions
- `last_session_stats.json` - Stats for the most recently ended session

## 🛠️ Troubleshooting

### Aliases Not Working

```bash
# Reload your shell config
source ~/.bashrc  # or ~/.zshrc

# Or restart your terminal
```

### Git Hooks Not Working

```bash
# Check the hook exists and was generated by pre-commit
# (git finds the hooks directory, in a worktree too)
head -2 "$(git rev-parse --path-format=absolute --git-path hooks)/post-checkout"
# Should include: # File generated by pre-commit

# Reinstall all hooks if not
uv run --frozen pre-commit install
```

### Metrics Not Tracking

```bash
# Check if metrics directory exists
ls -la ~/.pyeye/metrics/

# Test the metrics script directly
uv run --frozen python scripts/dogfooding_metrics.py --help   # bare `python` needs the project's .venv activated
```

### Worktree Issues

A worktree shares the main repository's hooks, so `pre-commit install` in any
checkout installs them for all. To see where they are:

```bash
git rev-parse --path-format=absolute --git-path hooks
```

## 🔄 Updating

To update the automation setup:

```bash
# Remove old aliases from ~/.bashrc or ~/.zshrc
# (the "# Dogfooding Metrics Aliases" section, through "# End of Dogfooding Metrics Aliases")

# Re-run setup
bash scripts/setup_dogfooding.sh
```

## 🛠️ Individual Components

If you prefer to set up components individually:

```bash
# Install just git hooks
uv run --frozen pre-commit install

# Install just shell aliases
bash scripts/setup_aliases.sh

# Test the metrics CLI directly
uv run --frozen python scripts/dogfooding_metrics.py --help
```

## 📊 Checking Your Progress

```bash
# Daily check
dogfood-report --days 1

# Weekly check
dogfood-report --days 7

# See specific session details
cat ~/.pyeye/metrics/history.jsonl | tail -1 | python -m json.tool
```

## 🚨 Important Notes

- The automation only works when you're in a project with `scripts/dogfooding_metrics.py`
- Git hooks are installed per-repository (not global)
- The `grep` and `cd` wrappers work in every directory but only track in a
  checkout that has `scripts/dogfooding_metrics.py`
- Tracking writes only to `~/.pyeye/metrics/`; the dogfooding scripts send
  nothing over the network
