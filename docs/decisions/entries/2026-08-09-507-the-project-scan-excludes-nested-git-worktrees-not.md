## 2026-08-09 — the project scan excludes nested git *worktrees*, not gitignored files (#507)

**Friction:** `.claude/worktrees/` is this repo's documented, tooling-enforced location for isolated worktrees (`02-session-startup.md`, `04-agent-triggers.md`), and nothing in `EXCLUDED_DIRS` skipped it — there is no `.claude` entry and no general hidden-directory rule. Every checked-out worktree therefore contributed a **second full copy of the project** to the whole-project name index: measured 362 of 3663 scanned `.py` files with one worktree present, giving `JediAnalyzer`, `resolve_canonical` and every other project symbol two definition sites. It did not visibly misfire only because the duplicate deduped downstream on canonicalization — luck, not a designed guarantee, and it degrades the moment the sibling branch diverges (renamed symbol, shifted line, deleted definition). The configuration that triggers the bug is the recommended one.

**Decision:** Exclude directories *strictly below* the scan root that are **linked worktree roots**. The invariant is **"don't index nested checkouts,"** not "don't index gitignored files." Rejected: respecting `.gitignore` / `git check-ignore` (most principled on paper, but it adds a git dependency to the scan path, breaks non-git projects, and would drop gitignored-but-imported generated code); and adding `.claude` to `EXCLUDED_DIRS` (special-cases one tool's convention, still misses worktrees created anywhere else, and coarsely excludes any other Python under `.claude/`). Submodules are deliberately still scanned — their source is frequently genuinely imported by the parent, and a user who wants another tree indexed already has `configure_packages`. **Detection reads git's structure, not the pointer's presence or path shape.** The first cut of this fix tested only for a `.git` **file**, on the stated belief that submodules keep a `.git` directory; that has been false since git 1.7.8 — `git submodule add` also writes a `.git` file (`gitdir: <super>/.git/modules/<name>`), so the rule as shipped silently dropped **every submodule** from the scan, the exact absence-without-a-signal failure this project exists to avoid. Review caught it before merge. The two are told apart by git's own marker: a linked worktree's gitdir (`<common-dir>/worktrees/<name>`) holds a `commondir` back-pointer to the shared repository; a submodule's gitdir is a standalone repository and has none. Path shape is not used — a submodule checked out at `worktrees/lib` has `worktrees` in its gitdir path too. Only when the gitdir is *missing* does the pointer's layout decide, covering the `git worktree prune` case where the checkout outlives its gitdir and is still a full duplicate tree. Known residue: this rule does not catch a *vendored nested clone*, which is noise by the same logic; left unsolved rather than guessed at. It also binds only `rglob_async` callers — `namespace_resolver.discover_namespace_packages` and the Django/Flask/Pydantic plugins call `Path.rglob` directly and still descend into nested worktrees (#517). The scan root itself is never probed, so pointing pyeye at a worktree — the documented workflow here — behaves normally. Prune-during-traversal was considered and **rejected for this change**: `rglob_async` has 5 call sites with caller-supplied glob patterns, re-implementing glob matching in a bugfix invites a second bug, and it would move perf baselines into the flaky-timing cluster (#486). The parse cost the issue flags is dominated by parsing the extra files, not walking them, so the conservative fix captures nearly all of the win.

**Anchor:** `pyeye.async_utils.rglob_async` (applies to all callers, incl. `pyeye.scope_utils.parallel_search`, `JediAnalyzer.get_project_files`, `PluginBase.get_project_files`); #507, #470.

**Verify:** gold — `tests/integration/test_nested_worktree_exclusion.py`: `get_project_files(pattern="*.py", scope=s)` returns no path with `".claude" in f.parts` for `s` in `{"main","all"}`, and `_search_all_scopes("StatusTracker", scope="all")` returns exactly one definition when the symbol is duplicated into a nested worktree. Rule-level and boundary cases in `tests/unit/utils/test_async_utils.py::TestRglobAsyncNestedCheckouts`: a worktree at any depth is excluded, including one whose gitdir was pruned away; a submodule is still returned, including one checked out at a path named `worktrees/`; a `.git` file that is not a gitdir pointer is not a worktree; a scan rooted *at* a worktree still returns its files. Those fixtures are hand-built, which is what let the original wrong layout pass — so `tests/integration/test_nested_worktree_exclusion.py::TestAgainstRealGitLayouts` builds a repo with `git submodule add` and `git worktree add` and asserts the scan returns the submodule's file and not the worktree's. It fails against the pre-fix implementation (verified: returns `['app.py']`, dropping `vendor/library/lib.py`).
