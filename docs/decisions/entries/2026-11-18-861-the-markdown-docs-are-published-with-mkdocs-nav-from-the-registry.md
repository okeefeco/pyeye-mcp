## 2026-11-18 — The Markdown docs are published with MkDocs, at repo paths, with the nav from the doc registry (#861, amends #823)

**Friction:** #823 (D1) retired Sphinx and left Markdown under `docs/` as the only docs tree, but published nothing in its place. GitHub Pages kept serving the frozen Sphinx build ("PyEye Server Documentation", which still teaches the v1 tools), and reading Markdown on GitHub isn't friendly for users. The maintainer amended D1: Sphinx stays retired, and the docs are published again.

**Decision:**

- **MkDocs with Material renders the existing Markdown,** with no second copy and no templates. There's no API autodoc: the reference pages are already generated by `docs_facts`.
- **The site's pages and nav come from the doc registry,** never from a list of its own. `site.is_published` takes registered pages for human or both audiences that aren't skills. It holds back a `history` page that still has honest-claims seeds (the migration guide, api-redesign and the two metrics records, until #830 clears them; the rule then lifts itself). A page's `DocEntry.site` overrides the default on the entry itself: the PR template, `changes/` and `.claude/README.md` are `site=False`. There's no path rule in the generator, because that would be a hidden second list (C16). `site.nav` groups the pages by folder. `mkdocs.yml` lists no pages, and a test fails if it gains a `nav:`. So a page reaches the site only by being registered and checked (the #818 anti-goal: no parallel list of files).
- **Site paths are repo paths.** MkDocs won't take the repo root as its docs folder, yet README, CONTRIBUTING and SECURITY live there. So a hook (`scripts/mkdocs_hooks.py`, a plain `hooks:` file, with no plugin dependency) serves every published page at its repo-relative path. README.md is the home page, and a relative link resolves the same way on GitHub and on the site. A link to a repo file the site doesn't publish is pointed at GitHub in the rendered page only; the source is untouched.
- **Built strictly in the existing required `pre-commit` job,** which runs on `merge_group`, so a broken link fails the PR with no new required check. It is deployed by `.github/workflows/docs-site.yml` on push to `main` only, through GitHub Actions (`upload-pages-artifact` + `deploy-pages`), with `pages: write` and `id-token: write`. The Pages source setting is the maintainer's; they chose Actions deployment.
- **A `docs` dependency group** (MkDocs, Material), with floors at the locked versions and capped majors, gets its own Dependabot group. Only the docs steps install it, and the server never imports it. pip-audit covers it, through the `pre-commit` job's environment.
- **Rejected:** a hand-written `nav:` checked against the registry, which is a second list kept in step by a test; a build step copying the root pages into `docs/`, a second copy at build time that would move their links; `mkdocs gh-deploy` to the `gh-pages` branch, a workflow that pushes to a branch (the maintainer picked Actions deployment).

**Anchor:** `pyeye.docs_facts.site.published` / `nav` / `rewrite_links` / `github_link`; `scripts/mkdocs_hooks.py`; `mkdocs.yml`; `.github/workflows/docs-site.yml`; the `pre-commit` job's "Docs site builds" step in `.github/workflows/ci.yml`; amends `2026-11-17-823-sphinx-is-retired-markdown-under-docs-is-the-only-docs-tree.md`; design C16; #861, #823, #818.
**Applies-to:**

- what's published, and the nav: `pyeye.docs_facts.docs.DocEntry.site`, `pyeye.docs_facts.site.published`, `pyeye.docs_facts.site.is_published`, `pyeye.docs_facts.site.nav`, through `scripts/mkdocs_hooks.py`;
- link handling: `pyeye.docs_facts.site.rewrite_links`, `pyeye.docs_facts.site.github_link`;
- the site config, with no page list: `mkdocs.yml`;
- the gates: the "Docs site builds" step in ci.yml's `pre-commit` job; the deploy workflow `.github/workflows/docs-site.yml`;
- the `docs` dependency group in `pyproject.toml`, and its Dependabot group.

**Verify:** PARTIAL. Gold: `uv run --frozen --group docs mkdocs build --strict` exits 0, and `uv run pytest tests/test_docs_facts_site.py tests/test_sphinx_retired.py` passes. That covers the publish rule, a nav equal to the published set, no `nav:` in `mkdocs.yml`, the link rewrites, and no Sphinx package. Unverifiable here: that the deploy succeeds, which needs the Pages source set to "GitHub Actions" and a push to `main`.
