## 2026-06-21 — namespace packages anchored through resolve/inspect (closes #444; re-extends count==expand)

**Friction:** #443's submodules enumerator handled PEP 420 namespace packages, but the cold-start chain couldn't anchor a *top-level* namespace package: Jedi surfaces a no-`__init__.py` package as an unanchored external symbol with an empty `module_path`, so `resolve("acme")` returned ambiguous externals, `inspect` mislabelled it `kind:variable`, and `outline`/`expand("submodules")` returned empty — defeating cold-start for namespace-rooted projects (the exact "tool can't start the conversation" case #423 set out to fix). #443's decision-log entry scoped count==expand to regular packages and deferred this to #444.
**Decision:** Anchor a top-level namespace package to a directory handle through resolve/inspect (`location.file` is the package directory, never byte-read — consistent with the submodules dir-anchored stub contract). A new SoT `canonicalization.find_namespace_package_dirs` (below the operations layer, so `resolve` — which can't import `edges` — can use it) is shared by resolve (`_anchor_namespace_package`), inspect (`_find_jedi_name_for_handle` Case 1.5 + the `_is_package_path` gate covering `is_dir()`), and edges (its `_package_dirs` namespace branch now delegates to it, deleting the duplicate `_analyzer_roots` finder). This re-extends `inspect(pkg).edge_counts["submodules"] == len(expand(pkg,"submodules").stubs)` to namespace packages — reverses the 2026-06-21 "scoped to regular packages" deferral. Rejected: widening only inspect's gate without anchoring resolve (leaves resolve ambiguous, half-fixing cold-start); a separate namespace-dir finder per layer (the drift risk the shared SoT removes). The importable-dir filter the SoT applies is likewise single — `canonicalization._dir_shallow_qualifies` (the recursive-one-level rule-(a)/(b)/(c) check) is shared by both anchoring and the `submodules` enumerator (`edges` imports it). An earlier draft kept a second, stricter copy in `canonicalization` (rule (c) only checked for a *direct* `.py` in a child), so a namespace whose only content was a nested regular package (`widgets/sub/deep/__init__.py`) would ENUMERATE via `expand` yet FAIL to anchor via `resolve` — a fresh #444-class inconsistency; consolidating to one predicate removes it.
**Anchor:** `canonicalization.find_namespace_package_dirs` / `canonicalization._dir_shallow_qualifies`; `resolve._anchor_namespace_package`; `inspect._find_jedi_name_for_handle` / `inspect._is_package_path`; `edges._package_dirs`; #444 (closes the deferral in the 2026-06-21 #443 entry).
**Verify:** gold — over `tests/fixtures/ns420` (a namespace-rooted project, no `acme/__init__.py`): `resolve("acme")` → `{found, scope:"project", handle:"acme"}` (not ambiguous), `inspect("acme")` → `is_package:true` with `edge_counts.submodules == 4 == len(expand("acme","submodules").stubs)`, and `outline("acme")` surveys `{acme.auth, acme.api, acme.plugins, acme.core}`. The anchor==enumerate shared-filter invariant is guarded over `tests/fixtures/ns420_nested` (`resolve("widgets")` anchors the rule-(c) nested-regular-package corner that `expand` enumerates). Covered by `tests/test_namespace_package_anchoring.py`.
