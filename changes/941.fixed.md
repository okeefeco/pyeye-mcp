- `find_django_views` finds the views it used to miss:
  - class views with an attribute base such as `generic.ListView`, or an aliased import;
  - `async def` function views;
  - the modules of a `views` package;
  - files that import Django with `import django…` rather than `from django`.

  A class with two view bases is now one record, not two. A base counts only when the module imports it from Django, so a project class whose name merely contains `View` is no longer reported (#941).
- **Django REST framework views are no longer reported.** Subclasses of DRF's `APIView`, `GenericAPIView` or `ViewSet`/`ModelViewSet` don't count, because their bases come from `rest_framework`, not Django. The old name-only check counted them. An explicit DRF rule is #947.
