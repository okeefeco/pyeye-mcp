- A definition whose header uses syntax pyeye's parser (Jedi's parso 0.8.7) doesn't support no longer produces phantom answers (#1074). The cases are PEP 646 `*args: *Ts`, `tuple[*Ts]` as an annotation and `Generic[*Ts]` as a base, and PEP 695 `[*Ts, **P]` type parameters and `type Pair[T] = ...`.
  - **Before:** parso dropped the `def` or `class` and left its body's names in the enclosing scope. So `members` listed them (Scrapy's `scrapy.utils.asyncio` showed `loop` and `asyncio`), and `resolve` answered for them.
  - **Now:** in a file parso error-recovers in, a name is a member, and resolves, only if Python's own parser binds it in that scope.
  - **The lost definition:** `resolve`, `inspect`, `expand` and `outline` answer not-found, with a detail naming its line and the parser, so you can Read it.
  - **Unaffected:** newer syntax inside a body (PEP 701 f-strings, `match`, `except*`, PEP 758) loses nothing, and is unchanged.
