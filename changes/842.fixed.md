- A relative path passed to a tool now resolves against `project_path`, not the server's working directory (#842, #843). This covers `resolve_at`'s `file`, `resolve`'s `path/to/file.py:42` and `path/to/file.py` forms, and a plugin tool's `package:<path>` scope. Before, a multi-project server looked in the wrong place, and `resolve_at` contradicted its own "relative to project_path" message. Absolute paths are unchanged.
- A plugin tool's `envelope` now lists a `package:<path>` scope whose directory doesn't exist in `unsearched_scopes`, spelled as you gave it. Before, such a scope searched nothing and returned `[]`, with only a server log warning (#842).
