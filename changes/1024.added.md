- A class defined in a function now has a handle in the subclass graph, in the notation `resolve`, `resolve_at` and `inspect` already used: `pkg.mod.func.Name`, or `pkg.mod.Cls.meth.Name` for one in a method, with a class nested in it named after it (`pkg.mod.func.Name.Inner`). It's named when it is one function level deep and its name is unique in that function, so `expand(…, "subclasses")` and `trace` now list such classes as stubs instead of in `handleless_subclasses`. One whose name is bound again in its function (a second class, a `def`, an assignment, `del`) stays handleless as `ambiguous_local`, and one two or more function levels deep as `nested_local`. Every newly named class resolves and round-trips through `resolve_at` (#1024).
- Handle segments are any Python identifier (PEP 3131), so a non-ASCII name such as `Héllo` is a handle that every tool accepts and returns (#1024).
- The `resolve` and `inspect` descriptions and the `python-explore` skill say that a handle is pyeye's name for a definition, not necessarily an importable path (#1024).
