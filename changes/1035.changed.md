- pyeye no longer guesses packages from the directories beside a project (#1035). With no `packages` configured, it used to add every neighbouring directory with a top-level `.py` file or a `setup.py`. That picked up unrelated projects, which were watched, swept and searched as project code: 562 directories for a project in a shared `/tmp`. It also missed the `pyproject.toml`-only repositories it was meant for. A package beside the project now comes from:
  - a path dependency in its `pyproject.toml` (see Added);
  - an editable install in its environment;
  - pyeye's own config.
  - **Migration:** a project that relied on the guess can declare the dependency, or add it with `configure_packages`. When a top-level import doesn't resolve, `resolve` and `inspect` now suggest both.
