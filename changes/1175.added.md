- The docs-facts `structure` kind takes its `areas` and `pairs` from committed data files (TOML, JSON or YAML), so a planner's curation arrives as a reviewable diff. A rejected pair, recorded as `rejected = "<reason>"`, is never labelled or listed as a candidate again. Every curated pair is now a fact, `<p>.pairs.<area>`, labelled or "possible duplicate (unverified)", which an area doc's "Similar elsewhere" footer can bind. With areas configured, a module in no area is a coverage gap, and `imported_by` is the set of importing areas (#1175).
