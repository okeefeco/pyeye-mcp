- In a PEP 420 namespace package under `src/` that holds a module named after itself (Poetry's `src/poetry/poetry.py`), `imports`, `callees` and `superclasses` now resolve the project's own imports (#1079).
  - **The cause:** Jedi's per-file "smart" `sys.path` walk added the namespace directory itself (`src/poetry`) to the search path. On it, `import poetry` found that module first, and a regular module wins over a namespace package, so every `poetry.*` import from inside the namespace was unresolved.
  - **The fix:** pyeye now leaves out any walk entry inside one of the project's import roots (`src`, a configured package).
  - **Unchanged:** flat layouts keep Jedi's walk.
  - **Measured on Poetry 2.5.2:**
    - `expand("poetry.packages.direct_origin", "imports")` went from 4 resolved and 10 unresolved to 12 and 2; the 2 are `poetry-core`, which isn't installed.
    - `LegacyRepository`'s superclass is `HTTPRepository` again.
