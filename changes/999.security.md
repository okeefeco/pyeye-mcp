- A definition reached through a symlink into a restricted directory (`/etc`, a credential store such as `~/.ssh`, and the rest of the deny-list) is no longer returned. A symlink inside the project, or inside its virtualenv's `site-packages`, could point Jedi's import lookup there, and `resolve`, `inspect`, `outline`, `expand` and `trace` returned the target's symbols and location. Such a definition is now not found (`unresolved`, with a detail naming the reason), and an `imports`, `superclasses` or `callees` edge lists it in `unresolved_imports` or `unresolved_superclasses`, or counts it in `unresolved_call_sites`, instead of returning a stub. Symlinks into any other directory, and a symlinked project root, work as before (#999).
