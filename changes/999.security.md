- A definition reached through a symlink into a restricted directory (`/etc`, a credential store such as `~/.ssh`, and the rest of the deny-list) is no longer returned or read. A symlink inside the project, or inside its virtualenv's `site-packages`, could point Jedi's import lookup there. `resolve`, `inspect`, `outline`, `expand` and `trace` then returned the target's symbols and location, and a project class or alias could show the target's signature, parameter defaults or base class, as could `trace_model_inheritance`'s inherited fields. Such a definition is now not found (`unresolved`, with a detail naming the reason). An `imports`, `superclasses` or `callees` edge reports it by the source's own spelling in `unresolved_imports` or `unresolved_superclasses`, or counts it in `unresolved_call_sites`, and a signature drawn from it is omitted. Symlinks into any other directory, and a symlinked project root, work as before (#999).
