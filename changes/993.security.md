- pyeye's Jedi helper process now always runs the server's own Python interpreter. Before, when `VIRTUAL_ENV` or `CONDA_PREFIX` was set in the server's environment, Jedi started the interpreter of that environment instead. That could be the interpreter of a virtualenv shipped inside an analysed repository, if the server was started with it activated. The project's environment is now read from disk (its `site-packages` and the plain-path lines of its `.pth` files), and its interpreter is never run. A `.pth` line that would run code is skipped (#993).
