- Every caller-supplied path now goes through the input check in the form the tool finally uses: a relative path anchored on `project_path`, checked as spelled and with symlinks followed. Before, a relative path without `..`, `resolve`'s file forms (`f.py`, `f.py:42`), a plugin `scope="package:<path>"`, `configure_packages`' `namespaces` paths and `standalone_dirs`, and config-file namespace and standalone paths skipped the check. A refused tool argument is now an error, never a "not found". A refused config entry is skipped with a warning (#856).
- A directory that pyeye scans (a plugin scope, or a configured package, namespace or standalone dir) may no longer be `/`, or any other ancestor of a restricted system directory. This includes the scan that `project_path="/"` implies, so scope `main` from `/` is refused with an error. `project_path` itself and single-file inputs are unchanged. Every directory walk also skips restricted directories it reaches through a symlink (#856).
- Config entries (`.pyeye.json` packages, namespaces and standalone dirs) that resolve to a restricted path, or to an ancestor of one, are now skipped and only logged as a warning. The caller isn't told yet; reporting skipped entries in the response follows in #898 (v2.2.0).
