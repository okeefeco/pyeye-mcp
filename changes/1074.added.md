- The definitions pyeye's parser couldn't read are now listed wherever members are measured (#1074):
  - `expand(<container>, "members")` and every `outline` node whose members were measured carry `unreadable_definitions: [{name, kind, line, reason}]`, with `reason` `parser_unsupported_syntax` and entries sorted by line. It is `[]` when none were lost.
  - `inspect` carries `unreadable_definition_count` beside `edge_counts.members`.
  - `trace` following `members` carries `unreadable_definition_counts`, a `{handle: count}` map.

  Python parses these files: the names describe pyeye's limit, not broken code.
