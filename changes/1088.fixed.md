- An `@overload`'ed function or method now resolves to its implementation, the definition without `@overload`, instead of its first overload stub. `resolve`, `resolve_at` on any of its definitions and `inspect` report the implementation's location and `deprecation`, and `expand(..., "callees")` reads the implementation's body, where it returned an empty list from the stub's `...`. A definition with only overloads (a `.pyi`, a Protocol) keeps the first overload. `inspect`'s `signature` for an overloaded function is unchanged for now: which signature to report is being decided (#1088).
