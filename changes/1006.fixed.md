- The `subclasses` edge (`expand` and `trace`) no longer under-reports or gives a subclass a handle it doesn't have. The class graph used to key every class by `module.Name`, so a same-named class nested in a function or in another class overwrote the module-level one and took its handle, and every file with no importable module path (such as `migrations/0001_initial.py`) fell back to its file stem, so same-named classes in different apps collapsed into one. On django that hid a large share of the direct subclasses of `Model`, `ModelAdmin`, `Form` and `Migration` (measured in #1006). Each class is now keyed by where it's defined, and counted once:
  - a class nested in a class gets its real handle, `module.Outer.Inner`;
  - a class that can't be named (one in a nested function, one whose name is defined twice in its function, or one in a file with no module path) is no longer reported under someone else's handle. It's counted and listed in the new `handleless_subclasses` fields instead (see Added) (#1006).
- `find_django_views` reports a class view defined in a function once per definition, instead of merging same-named ones or failing (#1006).
