- A class defined inside a function no longer reports a false `0` for its members. Jedi names such a class (`pkg.mod.outer.Local`) but leaves its members unnamed, so `inspect`'s `edge_counts.members` read `0` and `expand(…, "members")` returned `[]` for a class with a body. Its members are now read from the class itself and named after it (`pkg.mod.outer.Local.x`), and those handles work in `resolve`, `resolve_at` and `inspect`. A class inside a nested function, and the members of two local classes sharing one name, still have none (#1025).
