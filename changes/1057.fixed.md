- `expand(<class>, "subclasses")` no longer changes between sessions for a class whose base is imported through a try/except shim (`try: from ._fast import Local` / `except ImportError: from ._slow import Local`, or the standard library's `threading.local`). The class graph used to key such a base by the first of Jedi's goto results, whose order differs between processes and even between rebuilds. It now resolves every base as `superclasses` does: one class, or unresolved. A base that is ambiguous (imported by a try/except shim, or rebound by an if/else such as `if is_psycopg3: class Cursor` / `else: Cursor = psycopg2.extensions.cursor`) is unresolved in both edges: the class is in no candidate's `subclasses`, and `superclasses` lists that base in `unresolved_superclasses`. `subclasses` and `superclasses` now agree on every base, and django's class graph is identical across processes (#1057).
- A goto that returns several definitions of one name no longer depends on the order Jedi lists them in. That order differed between processes, so `callees`, `imports`, `superclasses`, `inspect` and type references could each resolve such a name in one session and not the next (#1057).
