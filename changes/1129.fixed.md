- A TypedDict class shows the keyword-only constructor its keys imply, such as `Movie(*, title: str, year: int | None)`, instead of `Movie()`, `dict`'s no-argument overload renamed (#1129). An optional key (`total=False` or `NotRequired[...]`) is marked `=...`, since it has no real default. `Required[...]` and `NotRequired[...]` override the class's totality for their key, and `ReadOnly[...]` isn't shown. A TypedDict that inherits keys shows them first, but only when every base resolves to one TypedDict class; otherwise it has no signature, never a partial one. The functional form, `TypedDict("Movie", {...})`, has no signature.
