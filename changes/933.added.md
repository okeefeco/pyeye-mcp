- A project module that exists only as a `.pyi` stub, with no `.py` beside it, now has handles everywhere, located at the stub (#933):
  - **Lookup:** `resolve` (dotted, bare name, `file`, `file:line`), `resolve_at`, `inspect` and `outline`.
  - **Edges:** `members`, `submodules`, `superclasses`, `subclasses` and `imports`.
  - **Precedence:** a `.py` beside a stub still wins, as before (#885).
  - **Imports:** a stub's own imports are declarations, not runtime imports, so `imported_by` doesn't count them, while `imports` on the stub module lists them. `imported_by`'s ceiling text says so.
  - **Vendored stubs:** a `foo-stubs/` directory inside a project still gets no handles, and none of its files are listed.
  - **Not covered:** a package that has only an `__init__.pyi` (#1004).
  - **Watching:** edits to a `.pyi` file now reach pyeye's caches, as `.py` edits do.
- `expand` and `trace` have a new unsupported `reason`, `"stub_declaration"`. `callees` returns it for a definition declared only in a stub (a project stub-only module, typeshed or a stub-only installed package), since a stub has no bodies to read (#933).
