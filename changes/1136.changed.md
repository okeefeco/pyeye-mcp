- The pyeye plugin is now the development setup: from a checkout or worktree, `claude --plugin-dir "$PWD"` runs that checkout's skills, hooks and MCP server (CONTRIBUTING, "Running your checkout in Claude Code"). The repository's `.mcp.json` is removed. Claude Code took it as the plugin's top, so `--plugin-dir` launched it instead of the plugin's server, and it never connected. Sessions in the repository now get pyeye from the plugin (tools `mcp__plugin_pyeye_pyeye__…`), not from a project `pyeye` server.
- The plugin keeps one environment per plugin directory (`${CLAUDE_PLUGIN_DATA}/venvs/<hash>`) instead of one shared `.venv`. Every `--plugin-dir` session shares one data directory, so two checkouts in dev mode ran whichever checkout had synced first. Environments of plugin directories that no longer exist are removed at session start. The old `.venv` is left in place and no longer used.
- In the pyeye repository, a session-start message warns when the pyeye plugin running isn't the session's checkout.
