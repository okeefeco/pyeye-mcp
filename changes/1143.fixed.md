- The server no longer waits for framework detection before it starts serving. Started in a large directory with no early Pydantic import (`$HOME`, a monorepo root), it used to walk the whole tree first: over a minute in one measurement, during which it answered nothing and didn't notice a client that had gone away. Detection now runs in the background once the server is serving. When it finishes, the detected framework's tools are registered and clients are told with a tools-changed event (#1143).
- Pydantic and Flask detection read the project's declared dependencies first: `pyproject.toml` (dependencies, optional dependencies, dependency groups, uv dev-dependencies, Poetry dependencies and groups), every `requirements*.txt` and `requirements/*.txt`, `Pipfile`, and `uv.lock` / `poetry.lock`. A declared framework, or one of its `<name>-*` extensions, is detected without a scan. A dependency is now matched by its name, not by the text appearing anywhere in the file (#1143).
- When nothing declares the framework, the import scan stops after 20,000 directory entries. Stopping there reports the framework as not determined rather than absent, so its tools aren't listed, but they still run when called by name (#1143).
